## 2 Sherlock 数据集分析

### 2.1 数据集概览

Sherlock 是一个电网信息物理安全仿真数据集，通过 Pandapower 对一个中压配电网络进行全潮流仿真，并注入网络攻击事件。从停电原因分析视角看，关注点在于其完整的逐秒电网状态时序数据——470 个字段覆盖了变压器、母线、线路、开关、负荷、分布式电源、储能等设备的实时运行状态，格式设计和字段体系具有参考价值。

**数据规模：**

| 项目 | 数值 |
|------|------|
| 时序记录数 | 训练集 + 测试集各 43,204 条（各 12 小时，约 1 秒/步） |
| 状态字段数 | 470个（覆盖母线、线路、变压器、开关、负荷、分布式电源、储能） |
| 标注事件 | 训练集 7 个良性运维事件，测试集 21 个攻击事件 + 7 个良性事件 |
| 攻击类型 | Industroyer（操控开关/负荷断连，直接停电）、drift-off（传感器数据篡改，不停电）、control-and-freeze（冻结 SCADA 画面，不停电）、arp-spoof-dos（通信中断，不停电） |

### 2.2 物理设备状态字段（从停电分析视角）

数据集的 470 个状态字段，按设备类型分组后，与停电原因分析的核心监测需求对应关系如下：

| 设备类型 | 字段数 | 关键监测量 | 对应停电分析场景 |
|---------|--------|-----------|----------------|
| `trafo`（变压器，2台） | 28 | 负载率、分接头档位、两侧电压/电流/功率、损耗 | 配变过负荷、绝缘击穿、分接头接触不良 |
| `bus`（母线，15个） | 60 | 电压（标幺值）、电压角、有功/无功功率 | 台区电压偏差、功率不平衡 |
| `line`（线路，15条） | 120 | 两端电流、电压、有功/无功功率 | 线路过载、电缆故障 |
| `switch`（开关，32个） | 64 | 合/分状态（`closed`/`is_closed`） | 断路器跳闸、开关误动 |
| `load`（负荷，18个） | 72 | 有功/无功功率、连接状态（`is_connected`） | 负荷失电、用户停电范围 |
| `sgen`（分布式电源，13个） | 104 | 有功/无功功率、目标功率、控制模式、连接状态 | 分布式光伏/储能接入异常 |
| `storage`（储能，2套） | 20 | 荷电状态（SOC）、充放电功率、连接状态 | 储能充放电冲击 |
| `trafo:tap_position` | — | 分接头档位（整数） | 分接头接触不良的典型特征量 |

### 2.3 可借鉴的点

**（0）Pandapower 仿真框架可用于生成雄安 400V 台区标注数据集**

Pandapower 是一个开源的 Python 电力系统仿真库，核心功能是**潮流计算（Power Flow）**：给定电网拓扑（母线、线路、变压器、负荷的连接关系）和设备参数（阻抗、容量等），计算出每条母线的电压、每条线路的电流和功率，模拟真实电网的运行状态。

Sherlock 使用 Pandapower 仿真中压电网，同样的方法可以直接用于构建雄安 400V 低压台区的仿真数据集：搭一个配变（10/0.4kV）+ 地下电缆 + 充电桩/光伏/储能的台区模型，用 Python 循环驱动时序负荷曲线，每步跑一次潮流计算，注入物理故障（配变过载、电缆绝缘击穿、三相不平衡等），直接得到带停电原因标签的时序状态数据集。若未来停电原因分析获取不到真实数据，可以采取这种方案。

Pandapower 本身只做稳态潮流计算，不内置故障仿真功能。主要工作量集中在两块：一是**设计雄安台区网络拓扑和设备参数**（配变容量、电缆阻抗、各类负荷接入位置等）；二是**在 Pandapower 外部实现每类故障的注入逻辑**，即通过修改模型参数来模拟故障——例如配变过载通过持续增大负荷超过额定容量来模拟，电缆绝缘击穿通过在对应线路上添加小阻抗接地支路来模拟，三相不平衡通过给三相设置差异化的单相负荷来触发。此外还需要编写包含充电桩/光伏/电采暖的日负荷时序曲线驱动时序仿真，使故障在真实负荷背景下自然触发——过负荷跳闸发生在夏季晚高峰、光伏逆流发生在白天满发时段，而不是在固定工况下人为注入，这样生成的样本更贴近实际运维场景。

**（1）时序状态快照格式**

数据集的每条记录包含三个字段：`timestamp`（Unix时间戳）、`state`（470个电网状态值的键值对）、`malicious`（事件标签）。这种"每秒一帧、每帧一份完整电网快照"的结构，本质上与雄安新区 TTU 采集数据的组织方式相同——TTU 也是按固定时间间隔上报配变温度、三相电流、电压等多维状态量。如果未来 低压配电网停电原因分析 要接入实时数据流做在线分析，可直接沿用这套格式，只需把 `state` 的 470 个字段替换为 TTU 监测量，`malicious` 替换为停电原因类别标签即可。

**（2）变压器负载率作为核心特征**

变压器的 `trafo.loading` 字段表示当前负载占额定容量的百分比，是随负荷变化连续波动的实时值。在仿真数据中可以观察到：攻击前 `trafo.0:loading` 稳定在约 29%，切断部分线路后降至 26%，电网重新调度后又回升。这个字段对应 低压配电网停电原因分析 判断逻辑中"负载率>100%持续30分钟→配变过负荷高置信度"的核心判据——它验证了负载率这个特征在仿真环境里是可以被精确连续记录的，因此用同样逻辑设计 TTU 数据采集指标是合理的。

**（3）开关状态与停电范围的联动**

开关（`switch`）在电网中相当于电路的"闸刀"，`switch.X:closed = True` 表示该开关处于合闸（通路）状态，`False` 表示分闸（断路）。数据集中可以直接观察到：industroyer 攻击操控 switch.13/14 分闸后，由这两个开关供电的 bus.5 节点电压立刻从正常值跌至 0，对应该母线下所有负荷（`load:is_connected`）同时断电。数据集中每个开关都同时记录了 `closed`（指令状态）和 `is_closed`（实际状态）两个字段，以及该开关下游所有 `load:is_connected` 的当前值。这套"开关状态 + 下游负荷连接状态"的联合记录方式，对应低压配电网停电分析中"断路器跳闸状态 + 停电用户范围"的特征设计，可作为字段定义的参考。

**（4）分布式电源和储能的状态字段设计**

`sgen`（分布式电源，对应光伏/小型发电机）和 `storage`（储能）的状态字段覆盖了两类设备的完整运行状态：是否在线（`is_connected`）、当前实际出力（`active_power`）、下发的目标出力（`target_active_power`）、是否处于外部控制模式（`explicit_control`）、储能荷电状态（`state_of_charge`）。这套字段体系与 低压配电网停电原因分析 数据需求清单中"分布式能源管理数据域"高度对应——雄安新区需要采集光伏逆变器的实时出力、储能的 SOC 和充放电模式，用于判断光伏逆流（2.4.1）和储能冲击（2.4.2）等停电原因，可以参考字段设计思路。

### 2.4 不能适配的点

1. **电压等级不匹配**：Sherlock 模拟中压环网（母线功率 30MW 量级），低压配电网停电原因分析 面向 400V 低压台区（配变容量 400～800kVA），两者设备参数、保护阈值和动作逻辑完全不同，数值无法复用。

2. **缺少 400V 低压专有字段**：配变油温、零序电流、三相不平衡度、漏保动作记录、重合闸结果、谐波畸变率（THD）等低压台区的核心判断特征在数据集中完全缺失，这些字段是 低压配电网停电原因分析 判断逻辑的关键输入。

3. **停电全由网络攻击触发，无物理故障场景**：数据集中所有停电均是攻击者直接操控开关/负荷连接状态产生的"人为断路"，不存在绝缘老化、接头过热、谐波污染等物理设备劣化过程，与 低压配电网停电原因分析 需要的物理故障样本因果结构根本不同。

4. **无停电原因类别标注**：标签字段 `malicious` 记录的是攻击事件 ID，而非停电原因分类。即便手动重标，也只能得到"外力断路"这一类，无法覆盖 低压配电网停电原因分析 所需的 34 个末端停电原因类别。


### 2.5 总结

| 维度 | 评价 |
|------|------|
| 数据格式 | ✅ 可借鉴：时序快照 + 事件标注的格式结构成熟，适合作为数据管道设计模板 |
| 物理字段设计 | ✅ 可参考：变压器、线路、开关、负荷、分布式电源的字段体系与 低压配电网停电原因分析 数据需求高度对应 |
| 电压等级 | ❌ 不适配：中压输电网，非 400V 低压台区 |
| 停电原因类型 | ❌ 不适配：全部为网络攻击触发的受控断路，无物理设备故障 |
| 低压专有字段 | ❌ 缺失：无油温、零序电流、谐波、漏保、管廊监控等关键字段 |
| 标注颗粒度 | ❌ 不适配：攻击事件 ID 标注，非停电原因分类标注 |

**结论**：Sherlock 可作为 低压配电网停电原因分析 数据管道设计和字段体系的参考，但无法直接用于训练或测试停电原因分析系统。国内公开的 400V 台区停电标注数据集缺口仍未填补。
